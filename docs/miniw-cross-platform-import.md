# 迷你世界跨端导入方案调研

## 结论

目前更适合“手机/电脑版通用”的流程，不是让玩家直接打开一个外部二进制文件，而是：

1. 在本工具中把神岛 `.gz` 地图转换成 Lua 建造脚本。
2. 在迷你世界开发者地图中运行脚本，把体素写入地图。
3. 使用迷你世界游戏内的地图发布 / 云备份入口。
4. 手机端和电脑版都从官方地图/个人中心进入同一份地图。

`.miniwvox` 仍然保留为备用导出，因为它来自上游 `box3-gz-to-miniw` 的实现，但它不是迷你世界公开、稳定、跨版本的官方地图交换格式。将它作为主链路会遇到版本、权限和客户端入口不一致的问题。

## 为什么 Lua 主链路更稳

- Lua 是在迷你世界开发者地图内部执行，最终产物是游戏自己的地图存档，而不是依赖外部文件导入器。
- 地图发布和云备份是面向作品分发的官方流程，适合跨设备继续编辑和游玩。
- 3.0 创作工具已经将预制、资源和逻辑纳入资源管理，并支持打包为 MOD 后应用到存档地图；后续如果需要自定义方块/逻辑，可以把同一套转换结果扩展成 MOD 资源包。

## 操作建议

### 适合个人快速导入

- 导出 Lua。
- 创建开发者地图，粘贴或加载脚本。
- 运行脚本完成建造。
- 关闭脚本建造逻辑，保存地图。
- 发布或云备份地图。

### 适合批量发布

- 将地图脚本、资源和逻辑整理成 3.0 创作工具的 MOD/预制资源。
- 在创作工具中测试后发布。
- 让玩家在自己的存档地图中下载并应用 MOD。

## 当前工具的格式策略

- `Lua`：主导出，面向跨端的官方地图流程。
- `.miniwvox`：备用导出，用于已有兼容导入器的桌面工作流。
- 预览、镜像和偏移：在导出前完成坐标校正，避免在手机端重复调整。
